# Функциональные требования

Идентификатор: `FR-<ДОМЕН>-<NN>`.

| Домен | Расшифровка |
|---|---|
| `ING` | Приём статусов рейсов |
| `DET` | Детекция сбоя |
| `IMP` | Оценка влияния |
| `ALT` | Подбор альтернатив |
| `NTF` | Уведомления |
| `DEC` | Принятие решения |
| `REB` | Перебронирование |
| `PLN` | Обновление плана поездки |
| `GRP` | Групповые поездки |
| `PII` | Паспортные данные |

Приоритет по MoSCoW: `M` — Must have, `S` — Should have. Каждое требование имеет
хотя бы один критерий приёмки в [критериях приёмки](./acceptance.md); требование,
описывающее правило из нескольких случаев, имеет по критерию на случай.

Список отфильтрован: включено только то, что следует из условия кейса или из
обязательных условий приёмки, проверяется критерием и не является уточнением
соседнего требования. Сквозные свойства — аудит решений, восстановление после
недоступности источника — вынесены в [нефункциональные требования](./non-functional.md).

## ING. Приём статусов рейсов

| ID | Требование | Приоритет | Актор |
|---|---|---|---|
| FR-ING-01 | Система принимает статусы сегментов из трёх типов источников — агрегатор статусов, push перевозчика или GDS, служебная рассылка на почту — и приводит их к единой модели статуса сегмента. Сообщение, из которого статус извлечь не удалось, направляется оператору поддержки | M | Источник статусов |
| FR-ING-02 | Для каждого принятого сообщения система сохраняет время события, время приёма, идентификатор источника и его ранг достоверности. Статусы сегмента накапливаются добавлением новых записей: ранее принятый статус не изменяется и не удаляется | M | Источник статусов |
| FR-ING-03 | Текущее состояние сегмента вычисляется из потока сообщений по правилу: повторно доставленное сообщение не создаёт статуса и не порождает детекции; сообщение со временем события более ранним, чем у текущего статуса от источника не ниже рангом, сохраняется, но состояния не меняет; при противоречии текущим становится статус источника с высшим рангом, а при равном ранге — с более поздним временем события. Факт противоречия сохраняется | M | Источник статусов |
| FR-ING-04 | Если возраст текущего статуса сегмента превысил порог свежести, сегмент переводится в состояние неопределённости. Отсутствие обновлений не трактуется как отсутствие изменений | M | Источник статусов |

## DET. Детекция сбоя

| ID | Требование | Приоритет | Актор |
|---|---|---|---|
| FR-DET-01 | Система детектирует по времени события типы сбоя: задержка сверх порога, отмена рейса, изменение времени вылета или прилёта, смена аэропорта, misconnect. Изменение, не влияющее на исполнимость плана — смена терминала, выхода на посадку, борта, — регистрируется как информационное и сбоя не создаёт | M | Система |
| FR-DET-02 | Misconnect детектируется сопоставлением фактического времени прилёта, времени вылета следующего сегмента и MCT для этой пары терминалов. Оба рейса при этом могут выполняться по расписанию | M | Система |
| FR-DET-03 | Пока по бронированию открыт сбой, новый статус того же типа обновляет его, а не создаёт второй. Статус, поступивший после применённого решения и делающий это решение неисполнимым, открывает новый сбой, связанный с исходным как повторный | M | Система |

## IMP. Оценка влияния

| ID | Требование | Приоритет | Актор |
|---|---|---|---|
| FR-IMP-01 | Система определяет затронутые сбоем элементы плана поездки — последующие сегменты, стыковки, трансферы, заезды в отель, активности — и затронутых участников поимённо, сопоставляя времена в UTC, и присваивает сбою класс влияния: план исполним, исполним с риском, неисполним. Класс определяет дальнейшую ветку обработки | M | Система |
| FR-IMP-02 | Среди затронутых элементов система выделяет невозвратные и оценивает денежные потери при их отмене | S | Система |

## ALT. Подбор альтернатив

| ID | Требование | Приоритет | Актор |
|---|---|---|---|
| FR-ALT-01 | Система подбирает альтернативные рейсы для сбойного сегмента в пределах заданного временного горизонта, сохраняя конечную точку маршрута, и ранжирует их по сохранению остального плана, затем по времени прибытия, затем по разнице тарифа | M | Провайдер бронирования |
| FR-ALT-02 | Каждая альтернатива проверяется на MCT по всем стыковкам получившегося маршрута | M | Справочник ограничений |
| FR-ALT-03 | Каждая альтернатива проверяется на багажный тариф: норма провоза сравнивается с нормой исходного билета | M | Справочник ограничений |
| FR-ALT-04 | Каждая альтернатива проверяется на транзитную визу по гражданству путешественника, аэропортам пересадки, длительности пересадки и необходимости покидать стерильную зону | M | Справочник ограничений |
| FR-ALT-05 | Каждая альтернатива проверяется на корректность в таймзонах: переход через полночь и через дату не приводит к неверному расчёту стыковок, трансферов и заездов | M | Система |
| FR-ALT-06 | Для каждой альтернативы система рассчитывает разницу тарифа и определяет, является ли перебронирование вынужденным | M | Система |
| FR-ALT-07 | Проверки ограничений выполняются до показа вариантов путешественнику. Результат каждой проверки сохраняется отдельно с исходом — годен, годен с условием, отклонён — и причиной. Вариант, отклонённый по жёсткому ограничению, не показывается и не может быть выбран авто-политикой | M | Система |
| FR-ALT-08 | Если годных альтернативных рейсов нет, система предлагает перенос затронутых активностей и трансферов в пределах существующего плана | S | Система |

## NTF. Уведомления

| ID | Требование | Приоритет | Актор |
|---|---|---|---|
| FR-NTF-01 | Система уведомляет затронутого путешественника по лестнице каналов, начиная с канала наивысшего приоритета. По одному сбою одновременно активно не более одного уведомления: новое заменяет предыдущее. Ограничения пользователя на каналы и время доставки не применяются к сбоям с классом влияния «план неисполним» | M | Путешественник |
| FR-NTF-02 | Переход к следующему каналу происходит при неполучении подтверждения доставки или ответа за отведённый шагу срок. Факт отправки подтверждением не считается. Статус доставки, полученный от провайдера канала, сохраняется и связывается с уведомлением | M | Провайдеры каналов доставки |
| FR-NTF-03 | Уведомление о сбое содержит: что произошло, какие элементы плана затронуты, предложенные варианты, срок ответа и то, что произойдёт при отсутствии ответа. Времена показываются в локальном времени своей точки с указанием таймзоны | M | Путешественник |
| FR-NTF-04 | Путешественник, не получивший уведомление вовремя, при следующем входе видит сбой, принятое решение и его основание, даже если ack-окно уже истекло | M | Путешественник |
| FR-NTF-05 | В поездке с несколькими участниками организатор видит сбой и его состояние по каждому затронутому участнику, участник — по своему бронированию. Изменение плана публикуется тем участникам, которых оно затрагивает | M | Организатор, Участник |

## DEC. Принятие решения

| ID | Требование | Приоритет | Актор |
|---|---|---|---|
| FR-DEC-01 | Система принимает выбор альтернативы от путешественника или от организатора с действующим мандатом в течение ack-окна | M | Путешественник, Организатор |
| FR-DEC-02 | Отсчёт ack-окна начинается с момента сдачи уведомления в первый канал лестницы. По истечении окна без ответа применяется авто-политика; авто-политика бронирования имеет приоритет над авто-политикой поездки | M | Система |
| FR-DEC-03 | Авто-политика выбирает только среди вариантов, прошедших проверку ограничений, и не принимает решение, требующее доплаты, если согласие на доплату в пределах порога не было дано плательщиком заранее | M | Система |
| FR-DEC-04 | Сбой, который система не может закрыть автоматически — нет годных вариантов, авто-политика не задана или неприменима, провайдер бронирования недоступен после исчерпания попыток, — эскалируется оператору поддержки вместе с историей сбоя, перечнем отклонённых вариантов и причинами отклонения | M | Оператор поддержки |
| FR-DEC-05 | Ответ, поступивший после закрытия ack-окна и применения решения, не отменяет применённое решение. Система сообщает о принятом решении и предлагает начать новый выбор | M | Путешественник |

## REB. Перебронирование

| ID | Требование | Приоритет | Актор |
|---|---|---|---|
| FR-REB-01 | Система выпускает перебронирование через провайдера по существующему PNR. Повторный вызов с тем же ключом операции не приводит к повторному выпуску: по одному сбою и одному бронированию не может быть выпущено более одного нового билета | M | Провайдер бронирования |
| FR-REB-02 | При вынужденном перебронировании тариф сохраняется и разница не начисляется. При добровольной смене рейса положительная разница тарифа авторизуется в платёжном шлюзе до выпуска билета и билет выпускается только после успешной авторизации, а отрицательная порождает возврат после успешного выпуска | M | Платёжный шлюз |
| FR-REB-03 | При неуспехе выпуска система компенсирует выполненные шаги: снимает авторизацию доплаты, восстанавливает отменённые наземные брони и возвращает сбой в состояние выбора альтернативы | M | Система |
| FR-REB-04 | При недоступности провайдера бронирования система повторяет попытку с нарастающим интервалом. Отказ перевозчика в перебронировании фиксируется с причиной, а отклонённый вариант не предлагается повторно в рамках этого сбоя | M | Провайдер бронирования |

## PLN. Обновление плана поездки

| ID | Требование | Приоритет | Актор |
|---|---|---|---|
| FR-PLN-01 | После успешного выпуска система заменяет сегменты в бронировании и в плане поездки, пересчитывает временную шкалу плана и сохраняет предыдущую версию плана с указанием сбоя, который её изменил | M | Система |
| FR-PLN-02 | Зависимые элементы плана — трансфер, заезд в отель, активность, — ставшие неисполнимыми, переносятся или отменяются у поставщика. Элемент, отмену или перенос которого поставщик не подтвердил, помечается требующим внимания | M | Поставщики наземных услуг |
| FR-PLN-03 | Невозвратный элемент плана не отменяется автоматически: решение по нему запрашивается у путешественника отдельно | M | Путешественник |

## GRP. Групповые поездки

| ID | Требование | Приоритет | Актор |
|---|---|---|---|
| FR-GRP-01 | Роль в поездке хранится на участии путешественника в поездке. Один и тот же путешественник имеет разные роли в разных поездках | M | Система |
| FR-GRP-02 | Мандат на принятие решений выдаётся организатору участником и отзывается участником. Организатор выбирает альтернативу только за тех участников, чей мандат действует на момент выбора | M | Участник, Организатор |
| FR-GRP-03 | Участник отказывается от общего решения для своего бронирования до момента выпуска билета, после чего его сбой обрабатывается индивидуально | M | Участник |
| FR-GRP-04 | Общее решение применяется к каждому участнику отдельной операцией перебронирования. Неуспех у одного участника не отменяет успешные перебронирования остальных | M | Система |

## PII. Паспортные данные

| ID | Требование | Приоритет | Актор |
|---|---|---|---|
| FR-PII-01 | Паспортные данные хранятся в контуре ПДн, отделённом от остальных данных системы схемой и правами доступа | M | Система |
| FR-PII-02 | Смежные подсистемы и внешний программный интерфейс оперируют ссылкой на запись контура ПДн и маскированным представлением. Метода, возвращающего полные паспортные данные, во внешнем интерфейсе нет; организатор поездки не имеет доступа к паспортным данным участников | M | Система |
| FR-PII-03 | Срок удержания паспортных данных отсчитывается от даты завершения поездки и хранится вместе с записью. По истечении срока запись удаляется физически; пометка об удалении без удаления содержимого требованию не удовлетворяет. Планировщик формирует отчёт об удалении за период и поднимает алерт при обнаружении записи с истёкшим сроком, которая не была удалена | M | Планировщик удержания ПДн |
| FR-PII-04 | Каждое обращение к паспортным данным записывается в журнал доступа: субъект доступа, время, сбой или операция, обоснование | M | Система |
| FR-PII-05 | Доступ оператора поддержки к паспортным данным выдаётся по конкретному сбою, с указанием обоснования и на ограниченный срок, по истечении которого прекращается автоматически | M | Оператор поддержки |
| FR-PII-06 | Провайдеру бронирования передаётся минимальный набор полей документа, необходимый для выпуска перевозки. Переданные значения не сохраняются в журналах и трассировках | M | Провайдер бронирования |
| FR-PII-07 | Путешественник инициирует досрочное удаление своих паспортных данных. Удаление выполняется, если по бронированию нет предстоящей поездки | S | Путешественник |

## Покрытие обязательных условий

Шесть обязательных условий кейса в части требований. Каждое закрыто явными
требованиями, а не подразумевается.

| Условие из задания | Требования |
|---|---|
| Данные о рейсах приходят с задержкой | FR-ING-02, FR-ING-03, FR-ING-04, FR-DET-01, FR-DET-03 |
| Пользователь может быть оффлайн | FR-NTF-01, FR-NTF-02, FR-NTF-04, FR-DEC-02, FR-DEC-03, FR-DEC-05 |
| Альтернативы учитывают багаж, визы, таймзоны | FR-ALT-02, FR-ALT-03, FR-ALT-04, FR-ALT-05, FR-ALT-07, FR-IMP-01 |
| Паспортные данные не хранятся дольше нужного | FR-PII-01 … FR-PII-07 |
| Групповые поездки | FR-GRP-01 … FR-GRP-04, FR-IMP-01, FR-NTF-05 |
| Отказы внешних API | FR-ING-04, FR-DEC-04, FR-REB-03, FR-REB-04, FR-PLN-02 |
